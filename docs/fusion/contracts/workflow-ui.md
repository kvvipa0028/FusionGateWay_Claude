# 工作流与设计检查点页面

WP-19-WORKFLOW-UI-01，在已有 Magpie 样式任务表单与详情区小范围扩展：一个任务类型选择、一个默认折叠的设计检查点。复用原列表、按钮、表单、颜色变量与换行布局；原 app.css/app.js/index.html、Fusion editor.css 及导航未改，没有第二套框架。当前仍为 Fusion 补充视图，原主界面全部页面整合和真实三路线 Gate A 未完成。

## 创建与附加

1. 选择已登记项目和“本次任务”。默认仍为原手动单阶段；调查与规划固定 design，独立审查固定 review，工程变更/问题修复固定五角色。各角色使用用户的当前绑定，不指定模型品牌。
2. 预览核对完整冻结计划、具体目标、effort、路线/账号/计费与预算。类型仅决定 required_roles，原 Task 提交请求及私有恢复记录不增加客户端权限字段。
3. 原“冻结提交任务”及跨窗口原请求恢复流程保持不变；保存成功不启动阶段。恢复区始终展示原冻结角色，不从当前类型猜测原流程。
4. 在任务详情展开“工作流与设计检查点”，明确选择与冻结角色一致的流程，点击“附加所选流程”。流程种类与当前完整 Task ETag 经[管理接口](workflow-api.md)校验。界面不自动猜 kind 或附加；重新打开后可以选择同冻结角色的 kind，但已有不可变种类不能替换。

附加必须在新任务 ready、generation=0 且没有任何 run 或 pending start 时完成，最终由 Store 事务检查；generation 因闲置暂停/继续增加后也不能补挂。应先明确附加，再进行状态操作。页面中的多角色任务在附加之前禁用启动，避免将五角色计划误当作可自由跳步的流程；旧单阶段默认和原未附加手动 API 合同不变。附加不改变读写权限、调用预算或模型配置。

## 设计与批准

已附加流程由服务端提供 next/blocker。页面只能明确启动允许的下一角色，运行、失败、停止未证实、缺少设计/批准或流程结束时保持启动禁用；原 pause/continue/cancel 的合同不变。只读回读不触发 start、resume、模型或额度查询。

成功 design 运行在后续完整任务回读时可填入原 run ID；run.succeeded 本身不能证明已可靠停止释放。等待 workflow.design_required 后，填写范围、约束、接口、验收标准，每行一项；目标始终取自原 Task。可手动填入已知同 Task design run ID，服务端须验证完整真实生命周期。当前是明确提交设计元数据，并非从模型输出自动生成或获得工程 Handoff。

“冻结当前设计”只提交 run_id 和完整 document，并校验回执与原输入逐项一致；设计与验收 hash 由服务端冻结，完整内容以 DOM/textContent 展示。HTML、目标或模型文本不作为代码/指令执行。相同任务回读保留尚未冻结的表单，切换任务清空表单及相关 run ID，避免跨 Task 冻结。

用户审阅完整范围、约束、接口、验收标准及两项 hash 后点击“批准当前方案”。确认提示绑定原 Task ID、当前计划及两项 hash；POST 携带完整 If-Match。批准回应必须属于同 Task/计划/方案，才展示“当前计划已批准”。新计划的旧批准不授权新计划，普通“继续派单”不能批准。批准不自动实施，也不替代 Factory/Runtime、OS 文件范围、预算或停止证明。

## 一致性与失败

任务详情将 workflow GET 纳入原 Task/Plan/Budget 回读：成功 Task ETag、项目、完整目标、计划 revision、精确四种定义/角色、当前设计/批准 hash 与 generation 关系必须一致。预算仍是独立计数，不宣称原子多资源快照。读失败清空详情/工作流，不能继续显示可执行的旧批准；未知/私有字段、其他 Task、跨计划批准均拒绝。

每个项目/Task 回读沿用原 epoch/detailSerial，旧任务的迟到 workflow 不能替换当前任务。附加/冻结/批准期间锁定编辑、任务切换和运行操作；请求结束后恢复原控件，不另开调度器。成功与拒绝均不发送 Idempotency-Key；这些内容不可变，原值可由 GET 核对。

写回复丢失、鉴权失败、Task 条件变化或异常成功回执时，保留原表单但禁用启动及后续工作流写入。用户明确“重新读取任务”，读取当前可信决定后再审阅；没有盲目重试或改 Task 条件。若批准真实提交而回复丢失，读取原批准后才能解除禁用，不再发送 approval/start。没有写 localStorage/sessionStorage 或把管理 token 放到页面。

## 验证和限制

复现沿用[任务工作台](task-workbench.md)的隔离 fixture 构建与 Node 浏览器命令。只执行本组件时，Node 增加 `--test-name-pattern='^workflow UI:'`；全工作台回归不加该参数。需要提前构建当前 CLI 与 `.fusion-dev/task-ui-fixture`，嵌入的 UI 必须与本次源码一致。浏览器使用临时 profile 和合成只读项目，不读取真实认证。

证据见[结果](../work-items/WP-19/WORKFLOW-UI-01/summary.md)。真实 HTTP、Controller/Scheduler/SQLite 配合合成 Runtime 验证设计完成/冻结/批准和失去回执/权限/当前条件的处理；浏览器截图是页面证据，不是实际 Wails 窗口操作或真实供应商生成。最终 T01–T60、Gate A、模型结果 Handoff/测试审查证据/有限返工仍未完成，Jev off。

回退仅恢复本组件 UI 资源并重新构建，不删除 schema9 记录、不修改数据库版本、不自动撤销已提交的人类决定。来源和 Native 固定路由继续遵守原管理接口及设计合同。
