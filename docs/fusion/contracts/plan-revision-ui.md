# 未来阶段模型修订界面

在原 Magpie 导航及现有 Fusion 任务详情旁增加默认折叠的“修改未来阶段模型”，复用已有三个选择区、五角色模型/effort控件与原 list/profiles/text/action 样式。原 Magpie 首页、脚本、i18n、六个 CSS 和 Fusion editor.css 均未修改；不新增页面、导航或框架。详见[证据](../work-items/WP-16/PLAN-REVISION-UI-01/summary.md)。

## 操作

1. 选择已保存任务，读取当前任务、计划和预算，展开“修改未来阶段模型”。
2. 点击“载入当前阶段选择”。若覆盖本次任务草稿或未保存的预设名称，须明确确认；取消时保持草稿。载入之后用上方原模型选择器修改本任务角色，两个独立设置自动展开；该任务未包含的角色控件及跨角色共用操作禁用。全局/项目配置不被修改。
3. 点击“预览阶段修订”。只提交相对冻结计划实际改变的必需角色，使用原计划强 tag，例如 `"1"`；不使用运行控制 tag，不发送 Idempotency-Key。未改变角色即使路线已退役，也不会被重新编译。请求不含目标、预算、账号凭据或工作流覆盖。
4. 核对当前任务 ID、新版本、改变角色的模型、账号、路线版本、effort、计费和 hash，再点击“应用已预览修订”并确认。应用仅发送原 preview_id/plan_hash 与原 If-Match，不自动启动或暂停阶段。
5. 成功后重新读取当前任务；旧 receipt 重读可能返回旧提交版本，当前任务可能已是更新版本。设计批准按既有服务端规则重新核对，历史和预算不重置。

未改变角色保持完整原绑定；改变角色的 required_capabilities 和 accept_primary_only 不被选择器暗中删除。继承使用服务器当前已保存的完整较低层配置；锁定/自动目标必须与明确选择和当前登记元数据一致。原 required_roles、independence 和预算上限亦核验，伪造/失效响应不启用应用按钮。开始过的角色由服务端拒绝修改，预览后开始的竞态在事务内再次检查。

## 失败与恢复

- 预览错误无持久影响。修改草稿使已有预览失效；到期需重新预览。计划/已启动角色冲突时结束修订，重新读取后审阅。
- 应用传输失败、异常成功响应、授权撤销或服务不可用时保留原 receipt/body/tag，只能重试同一阶段修订；禁止换项目、范围、模型、任务或启动新阶段。读取当前任务本身不解除未知结果。
- 原服务端明确拒绝该 receipt 时解除本次修订并重新读取。已提交 receipt 精确重读返回原提交计划，不生成新事件，不倒退当前计划。
- 当前窗口未知请求的关闭/刷新触发 beforeunload 提示。原 receipt 仍是既有服务器进程内记录，前端未新增持久 journal 或自动重放；浏览器/宿主重开必须先读当前计划，再明确预览。新预览强版本 CAS 仍由服务器保护，不能把页面重开或503当作原提交回滚。持续需要管理授权，不恢复执行准入。

当前证据是 Chrome 隔离浏览器→真实私有 Management HTTP/Store，与先前精确 Native bridge 的独立测试。实际 Wails 修订点击/像素、三路线真实准入、工程试点和最终T01–T60仍未验证；父WP-16继续in_progress，Jev off。
