# 当前需求摘录

来源为用户引用的 ChatGPT 对话“理解fusion含义”及本轮明确指示。这是本地摘录，不是原《Fusion_最终实施方案_v1.1.md》的重建。

## 产品目标

Fusion 是本人使用的自托管 AI 工作网关。以 Magpie 为源码基座，沿用 Go 与现有 GUI/CLI，增加阶段配置、受控任务执行、交接和证据管理。首台宿主为 Mac mini，首版采用单机服务与受管子进程。

## 阶段与模型控制

- 三个配置区域：设计与规划、实施与测试、审查与验收；展开为 `design`、`implementation`、`testing`、`review`、`acceptance` 五个角色。
- 用户可为各角色指定模型、账号、执行路径和支持的推理档位；具体模型不永久绑定角色。
- 配置优先级：本次任务 ＞ 项目配置 ＞ 全局默认。
- `locked` 必须使用冻结的指定目标；不可用时暂停，不暗换模型、账号、effort 或计费路径。
- `auto` 只在获准候选内选择；`inherit` 解析上层配置，不授予自由选择。
- 任务提交时冻结配置及版本。修订尚未开始的阶段需显式形成新版计划并重新准入，历史和当前执行不能被全局预设改动覆盖。

## 任务与证据

保留模型请求与 Agent 任务两种入口的语义区分。模型接口负责推理，工程任务通过真实受管 Runtime 读代码、修改独立项目副本和执行测试。

五阶段可以逐步交接，并管理取消、恢复、检查点和有限返工。Handoff 包含目标、固定代码版本、变更、真实验证结果及遗留问题；不同 Runtime 不共用原生 session ID。

编译、测试、静态检查和硬件验证以工具/设备结果为证据。验收模型不能把失败或缺失证据改成通过，源码或测试标准变更后需重新核对证据归属。

## 接入与调度

计划验证 Codex、Grok Build 和获准的 GLM 编码宿主。Runtime 适配完成与本人订阅真实可用分别验收；不以 fake 成功证明真实接入。

额度优先复用 Magpie/Runtime，CodexBar 用于缺口或对照。保留账号、共享池、单位、来源和更新时间，区分已知、未知、过期和耗尽。未知额度不能当作满额，额度不足不能自动增加费用或降低任务要求。

Jev/TypeSafe 后续可选，先旁路评估。最终权限、预算和模型选择由确定性策略控制；不得覆盖 locked。

## 实施边界

先做源码基线与隔离，再做阶段指定和手动版，之后做工程闭环，最后考虑自动路由。只读、写入、发布权限分别管理；方案文件不自动授权读取凭据、外发源码、提交、推送、发布或烧录。

本轮新增明确要求：使用最新上游源码、将文档加入项目仓库、正常处理 Fork 基础问题、将本机 Go 更新为 `go1.26.3`。这些准备工作不等于授权提前实现全部工作包。
