## 产品目标

Fusion 是本人使用的自托管 AI 工作网关。以 Magpie 为源码基座，沿用 Go 与现有 GUI/CLI，增加阶段配置、受控任务执行、交接和证据管理。按用户最新确认，首台宿主为当前本机，首版采用单机服务与受管子进程。实施计划及工作包中原有的 Mac mini 宿主表述以此决定为准，部署、隔离、备份与恢复的验收要求继续适用。

## 阶段与模型控制

- 三个配置区域：设计与规划、实施与测试、审查与验收；展开为 `design`、`implementation`、`testing`、`review`、`acceptance` 五个角色。
- 用户可为各角色指定模型、账号、执行路径和支持的推理档位；具体模型不永久绑定角色。
- 配置优先级：本次任务 ＞ 项目配置 ＞ 全局默认。
- `locked` 必须使用冻结的指定目标；不可用时暂停，不暗换模型、账号、effort 或计费路径。
- `auto` 只在获准候选内选择；`inherit` 解析上层配置，不授予自由选择。
- 任务提交时冻结配置及版本。修订尚未开始的阶段需显式形成新版计划并重新准入，历史和当前执行不能被全局预设改动覆盖。

## 任务与证据

保留模型请求与 Agent 任务两种入口的语义区分。模型接口负责推理，工程任务通过真实受管 Runtime 读代码、修改独立项目副本和执行测试。

五阶段可以逐步交接，并管理取消、恢复、检查点和有限返工。Handoff 包含目标、固定代码版本、变更、真实验证结果及遗留问题；不同 Runtime 不共用原生 session ID。

编译、测试、静态检查和硬件验证以工具/设备结果为证据。验收模型不能把失败或缺失证据改成通过，源码或测试标准变更后需重新核对证据归属。
