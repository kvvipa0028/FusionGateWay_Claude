# 项目副本的来源复核

`workspace.Copy(source, root, name)` 保持原接口。源目录必须由可信调用方批准，副本仍在 Git 外私有目录，文件 0600、目录 0700，不修改源。排除 `.git/.claude/.codex/.grok/.fusion-dev/.env`；不得把排除规则当作对其它文件的外发授权。

复制通过已打开的 `os.Root` 遍历和读取，拒绝 symlink、hardlink、特殊文件。打开文件使用 O_NOFOLLOW/O_NONBLOCK，读取前后核对 inode、类型、权限、UID/GID、链接数、长度和修改时间；每个文件返回前关闭描述符。保持最多 10000 文件、单文件 20MiB/总量 100MiB，并新增包含根目录在内最多 20000 个文件或目录，限制空目录树。超过任一限制不发布副本。

复制时私有记录包含所有实际纳入的文件和目录身份，以及文件内容 SHA256。发布前重新遍历整个源树，核对条目集合、身份、权限、文件时间与内容摘要；内容变化、新增/删除、相同内容换 inode、目录/根目录替换、链接和权限变化均拒绝，并清理本次临时副本。遍历固定到已打开目录，不因绝对源路径被替换而改读另一棵目录。

返回的 `Snapshot.SourceCurrent()` 使用同一私有来源记录复核，不信任公开的 `Path` 或 `Files`。调用方改变公开清单、修改生成副本，均不能改变原来源授权。零值、外部重建或反序列化的 Snapshot 没有私有记录，返回 false。来源记录只在内存中，不序列化为恢复授权；进程重启需按可信配置重新取得并验证来源，不能从任意公共 manifest 自动接管。

再次复核时，在读取文件 bytes 前拒绝未登记或身份已改变的条目。排除目录内部认证内容不读取、不记录、不复制；目录时间不单独作为文件清单依据，但目录 inode、权限、owner 和链接数仍核对。现有排除目录内部文件变化不影响源记录。

这是有界的文件系统状态观察，不是所有文件共享同一时间点的原子快照，不锁住用户或外部编辑器，也不能阻止复核后再次变更。调用方仍须落实当前项目登记、数据权限、可信私有目的目录以及每次实际派单/工具访问的检查。整个来源复核每次最多读 100MiB，不应宣称没有开销。后续 [SourceGuard](workspace-source-guard.md) 已接入可信 Controller、Grok/GLM Adapter、Supervisor 与归档检查；产品 bootstrap 的实际项目/准入绑定仍未完成，不把组件验证提升为 whole Source 实际准入或真实账号产品运行成功。目的目录并发替换/发布管理仍须由可信宿主落实。

证据见 [WP-11-SOURCE-SEAL-01](../work-items/WP-11/SOURCE-SEAL-01/summary.md)。macOS/arm64、Go1.26.3；其它平台实际运行未验证，Jev off，真实模型/额度调用 0。
